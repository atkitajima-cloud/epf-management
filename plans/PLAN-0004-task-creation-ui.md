# 目的

現在、新しいTaskを作る経路はAIチャットだけである。AIの判定に依存せず、画面のフォームから確実にTaskを作れるようにする。作成したTaskは既存の経路と同じく `tasks/EPF-nnnn.md` へ保存し、Kanbanへ反映する。

# 現状（事実）

- Task作成の呼び出し元は `POST /api/chat` の `create_task` のみである（`app/server.js`）。
- `/api/tasks` はGET（一覧）のみで、作成用のAPIがない。
- 画面のTask詳細ダイアログは既存Taskの編集専用である。
- `createTask()`（`app/lib/markdown.js`）は入力が不正でも既定値で補う。タイトルが空なら「新しいタスク」、Requirementが不正なら `REQ-0001` にする。AIチャット用の動作であり、画面からの入力では誤りを隠してしまう。
- Requirementを入力・管理する機能はアプリにない。`requirement` は必須項目だが、AIチャット経路が `REQ-0001` を自動で入れているだけで、実際の紐づけを表していない。
- `createTask()` は `flag: 'wx'` で書き込むため、同じIDへの同時作成は失敗する。

# 成功条件

- Kanban画面から「新規Task」を開き、必要な項目を入力してTaskを作成できる。
- 作成したTaskが `tasks/*.md` に保存され、画面再読込後もKanbanの指定した状態の列に表示される。
- 入力が不正な場合は補完せず、理由を画面に表示して保存しない。
- Requirementは空欄のまま作成できる。指定する場合は、実在しないRequirementを指定できない。
- 作成ダイアログの本文欄に雛形が最初から入っており、内容を確認・編集してから作成できる。
- 既存のAIチャットによるTask作成、Task編集、状態変更、WBS生成、ガント、Git操作を壊さない。
- DBやUI固有の永続データを追加しない。

# 対象範囲

## 実装する

- `POST /api/tasks`: Taskを新規作成し、作成したTaskを返す。
- `GET /api/requirements`: `requirements/*.md` のIDとタイトルを返す（画面の選択肢用）。
- 画面の「新規Task」ボタンと作成ダイアログ。
- 作成時の厳格な入力検証（APIと画面の両方）。
- テスト、README、必要に応じてテンプレートの更新。

## 実装しない

- Requirement、Decisionの作成・変更。
- Taskの削除、複製、IDの手入力。
- Kanban列内の「+」追加、一括作成、CSV取り込み。
- AIチャット経路の動作変更。ただし、本文の雛形とRequirementの既定値（`REQ-0001` を補わない）と `plan` の既定値の廃止は除く。
- 作成時の自動commit / push。

# 設計判断

1. **作成ロジックは既存の `createTask()` を共有する。** AIチャットと画面で作成処理が分かれると、Front Matterの形式や本文の雛形が食い違うため。
2. **検証だけを厳格にする。** `createTask()` に `strict` オプションを追加する。AIチャットは従来どおり補完し、画面からの作成は補完せず検証エラーにする。既定値は現在の動作のままにして、AIチャット経路への影響を避ける。
3. **入力項目は既存の編集ダイアログに合わせる。** タイトル（必須）、状態、担当者、優先度、開始日、期限、先行Task、Requirement（任意）、本文。`plans/` はこのアプリ自体の開発計画であり、管理対象のTaskとは無関係なので、Planの入力欄は設けない。画面から作成するTaskのFront Matterには `plan` を書かない。
4. **Requirementは任意にする。** 一覧から選ぶ形は維持し、ダイアログを開いたときは空（未選択）とする。空欄のままでも作成できる。指定された場合だけ、実在を確認する。あわせて、`requirement` を必須Front Matterから外す（`REQUIRED_FIELDS`、編集ダイアログの必須指定）。AGENTS.mdの「Taskは対応するRequirementを明記する。」は削除する。既存のTaskのRequirementは変更しない。AIチャット経路も、Requirementの指定がなければ `REQ-0001` を補わず空にする。
5. **先行Taskの実在確認を行う。** 存在しないIDが指定された場合はエラーにする。
6. **本文が空の場合は、次の共通の雛形を使う。** 画面とAIチャットで同じ雛形にし、作成経路やPlanは書かない。作成ダイアログを開いたとき、本文欄にこの雛形を最初から入れる。利用者は内容を確認し、編集して作成できる。全部消して空のまま作成した場合は、保存時に同じ雛形を入れ、空の本文を保存しない。本文が入力された場合は、その内容をそのまま使う。

   ```markdown
   # 背景

   （未記入）

   # 目的

   （未記入）

   # 完了条件

   - [ ] 
   - [ ] 
   - [ ] 

   # 関連

   （未記入）
   ```

   AIチャット経路の本文は、現在の「AI Chatから作成されたタスク。」と固定の完了条件から、この雛形に変わる。
7. **ID採番は既存の `nextTaskId()` を使う。** 同時作成でIDが衝突して `wx` が失敗した場合は、採番し直して数回だけ再試行する。
8. **成功時は201、入力不正は400を返す。** エラー文言は既存の `validateTask()` の日本語メッセージを使う。
9. **編集ダイアログとは別のダイアログにする。** IDが未確定な状態と保存済みの状態を1つのフォームに混在させないため。項目の並びと検証表示は共通の部品にして重複を減らす。

# 実装ステップ

1. `createTask()` に `strict` オプションと、Requirement・先行Taskの実在確認を追加する。
2. `requirements/*.md` を読む関数と `GET /api/requirements` を追加する。
3. `POST /api/tasks` を追加する（入力不正は400、成功は201）。
4. `index.html` に「新規Task」ボタンと作成ダイアログを追加する。ボタンはボードの見出し行の右側、Task件数表示の左に置き、色は主要操作（`primary`）とする。ヘッダーの操作（WBS生成、ガント、Pull、Commit & Push、更新）は画面全体やリポジトリへの操作であり、ボードへの操作であるTask作成とは分ける。
5. `app.js` にダイアログの開閉、Requirement選択肢（先頭は空欄）の読み込み、本文欄への雛形の初期入力、送信、エラー表示、作成後のKanban再読込を追加する。
6. テストを追加する（下記）。
7. `requirement` を必須項目から外す（検証、編集ダイアログ、WBS・ガントの空表示、AIチャット経路の既定値、AGENTS.md）。
8. READMEにAPIと画面操作を追記し、必須Front Matterの説明を直す。
9. 動作確認後、変更をGitコミットする。

# 検証

- **Markdown I/O**: 作成したファイルがFront Matterと本文を保ったまま読み戻せる。
- **API**:
  - 正常作成で201と `EPF-nnnn` が返る。
  - タイトル空、不正な状態、不正な日付、開始日が期限より後、実在しないRequirement、実在しない先行Taskで400になり、ファイルが作られない。
  - Requirementが空欄でも201で作成され、Front Matterの `requirement` が空になる。
  - 連続作成でIDが重複しない。
- **既存経路**: AIチャット経由の作成が従来どおり補完付きで動く。
- **画面**: 作成ダイアログから作成して、指定した列に表示される。不正入力でエラーが表示され、ダイアログが閉じない。ガント、WBS生成、Task編集が引き続き動く。
- `npm test` が通る。

# リスク

- 画面用の厳格な検証とAIチャット用の補完が混在し、動作が分かりにくくなる。→ `strict` オプションで明示し、テストで両方を固定する。
- `requirement` を任意にすると、Requirementなしの既存表示（ガントのRequirement絞り込み、WBS）で空欄が出る。→ 空の値を除外または「-」で表示し、テストで確認する。
- 同時作成でのID衝突。→ `wx` による上書き防止と再試行で対処する。
- 手で編集された不正なTaskがあると、先行Taskの実在確認や採番に影響する。→ `listTasks()` の `invalid` 扱いを確認し、採番は既存のIDだけを対象にする。

# 未決事項

未決事項はない。以下は決定済みである。

- 作成時の状態は選択式とし、既定はBacklogとする。
- 本文の雛形は設計判断6の共通の雛形とし、作成ダイアログの本文欄に初期入力する。
- Requirementは任意とする。空欄で作成でき、必須Front Matterから外す。
- Planは画面の管理対象に紐づけない。入力欄も設けない。

# 補足

- 既存のTask 11件の `plan: PLAN-0001` は変更しない。
- `createTask()` の `plan` の既定値 `PLAN-0001` は、AIチャット経路も含めて廃止する。新しく作るTaskに `plan` は書かない。既存Taskの `plan` の扱い（編集時に保持されること）は変えない。
