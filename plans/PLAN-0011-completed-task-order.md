# 完了済みTaskを完了日の新しい順に並べる

## 目的

KanbanのDone列で、最近完了したTaskを先頭に表示し、完了状況を下までスクロールせず確認できるようにする。

## 背景と判断

現行Taskには完了日がなく、Taskファイル名順で表示されるため、Done列の最新の完了をすぐ確認できない。

Task正本に任意の `completed_at`（`YYYY-MM-DD`）を追加する。EPF Managementの画面から `done` に遷移した時に、日本時間の日付を自動記録する。`done` から別の状態へ戻す時は `completed_at` を消去し、再完了時は新しい日付を記録する。作成時に `done` を選んだ場合も同様に日付を記録する。

Markdownを直接編集して状態を `done` にする場合は、完了日を推測・補完しない。既存の完了Taskも同様に日付不明のままとし、`completed_at` がある完了Taskの後ろへ置く。これは、Git履歴や期限から実際の完了日を推測して正本データを改変しないためである。完了日が同じ場合と日付不明Task同士はTask IDの降順で安定して並べる。

## 対象範囲

- `completed_at` のFront Matter直列化・検証・自動更新を追加する。
- Task一覧APIで、Done列に渡す完了Taskを `completed_at` の降順で並べる。
- KanbanのDoneカードに完了日を表示する。
- WBSへ完了日を出力する。
- 既存完了Taskは日付不明として扱い、順序のルールをテストする。
- Markdown I/O、状態変更、作成、並び替えの自動テストを追加する。

## 対象外

- 過去のGit履歴・期限からの完了日推測
- 完了日時（時刻）や完了者の記録
- 完了日を手動入力するUI
- ガントの日程表示の変更

## 実装ステップ

1. `completed_at` の日付検証と、日本時間の日付を取得する処理を追加する。
2. Task作成・更新・status更新で、`done` への遷移と差し戻しに応じて完了日を更新する。
3. Task一覧用の並び替えを追加し、完了Taskを完了日降順・日付不明を末尾・Task ID降順で返す。
4. KanbanカードとWBSに完了日を表示する。
5. 自動テスト、既存Task読込、ブラウザでの表示確認を行う。

## 検証

- `done` への遷移時に日本時間の完了日が記録されること。
- 差し戻しで完了日が消え、再完了で更新されること。
- Done列が新しい完了日順になり、日付不明Taskが末尾となること。
- 既存Taskを含めて読み込みとWBS生成が成功すること。
- `npm test` が成功すること。

## リスクと復旧

完了日の記録規則はTask正本に影響する。日付が誤って記録された場合は、対象TaskのFront MatterをGit差分で確認し、変更コミットをrevertできる。
