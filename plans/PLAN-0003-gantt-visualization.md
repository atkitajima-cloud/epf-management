# 目的

`tasks/*.md` を正本としたWBSをガントチャートで表示し、担当者が作業期間、進捗、期限超過、着手遅れ、依存関係を一目で確認できるようにする。

ガントチャートは新たな正本にせず、Task Markdownから都度組み立てる派生Viewとする。既存のKanbanと併用し、Kanbanは状態変更、ガントチャートは日程と遅れの把握に使う。

# 成功条件

- ブラウザからガントチャートを開ける。
- Taskの開始日、期限、状態、担当者、優先度、進捗、依存関係を確認できる。
- 今日の日付と計画期間を比較し、期限超過と着手遅れを見分けられる。
- Task Markdownを更新して画面を再読込すると表示へ反映される。
- 日程情報が不足するTaskを隠さず、要確認として表示できる。
- DBを追加せず、`tasks/*.md` をSingle Source of Truthとして維持する。
- 既存のKanban、Task編集、WBS生成、Git操作を壊さない。

# 対象範囲

## 実装する

- Taskの日程・依存関係スキーマ拡張
- ガント表示用データの組み立てと遅延判定
- 日単位・週単位で確認できるガント画面
- 担当者、状態、Requirementによる絞り込み
- 遅延・要注意・予定どおり・完了の表示
- Kanbanからガント画面への導線と、ガント画面からKanbanへの戻り導線
- Task詳細を開く導線
- 日程未設定、日付矛盾、依存関係不備の警告
- README、テンプレート、サンプルTask、テストの更新

## 実装しない

- ガント上のドラッグ操作による日程変更
- クリティカルパスの自動計算
- 工数、稼働率、休日カレンダーの厳密な計算
- ベースライン比較と完了実績日の管理
- 複数プロジェクト横断表示
- 外部サービスやDBへの保存
- ガントチャート専用ファイルの手編集

# 正本と派生View

```text
tasks/*.md
   ├─ Kanban
   ├─ views/wbs.md
   └─ ガントチャート画面
```

- ガントチャートは `views/wbs.md` を解析せず、Task Markdownを直接読み込む。
- `views/wbs.md` は引き続き表形式のスナップショットとして残す。
- ガント画面に表示する判定結果は保存せず、表示時に現在日付から再計算する。
- 日程変更は既存のTask詳細編集から行い、ガント画面は初期段階では参照専用とする。

# Task Markdownの拡張

既存項目を維持し、次の任意項目をFront Matterへ追加する。

```yaml
start: 2026-09-21
due: 2026-09-30
depends_on:
  - EPF-0003
  - EPF-0004
```

現在の簡易Front Matter Readerが配列を扱わない場合は、PoCでは次の1行形式を採用する。

```yaml
depends_on: EPF-0003, EPF-0004
```

実装時にReaderの能力を確認し、既存Markdownとの互換性を優先して形式を確定する。初期案は1行形式とする。

- `start`: 開始予定日。`YYYY-MM-DD`。未設定を許容する。
- `due`: 完了予定日。既存項目をそのまま利用する。
- `depends_on`: 先行Task ID。複数件はカンマ区切り。
- `progress` は追加しない。手入力の状態・チェックリストとの二重管理を避ける。

進捗率は本文の「完了条件」にあるチェックボックスから算出する。

- 全項目完了、または `status: done`: 100%
- チェック項目あり: 完了数 ÷ 全項目数
- チェック項目なし: `backlog` / `ready` は0%、`doing` は50%、`review` は90%を表示上の目安とする
- 目安値は「推定」と明示し、Markdownへ書き戻さない

# 表示内容

## 一覧部

ガント左側に次を表示する。

- ID
- Task名
- 担当者
- 状態
- 優先度
- 開始日
- 期限
- 進捗率
- 日程判定

行を選択すると既存のTask詳細を開けるようにする。初期実装で画面をまたいだダイアログ共有が複雑になる場合は、Kanbanへ戻って対象Taskを開けるリンクを付ける。

## チャート部

- 開始日から期限までを横棒で表示する。
- 完了率に応じて横棒内を塗り分ける。
- 今日を縦線で表示する。
- 期限超過は赤、要注意は橙、予定どおりは青、完了は緑、日程不足は灰色で示す。
- 依存関係は初期実装ではTask行のID表示とツールチップで確認できるようにする。矢印線は行数増加時に読みにくくなるためPoC対象外とする。
- 初期表示範囲は全Taskの最小開始日から最大期限までとし、範囲が広い場合は横スクロールする。
- 日単位と週単位を切り替えられる。初期値は週単位とする。
- 今日へ移動する操作を用意する。

## 集計部

画面上部に次の件数を表示する。

- 全Task
- 進行中
- 期限超過
- 要注意
- 日程未設定

集計カードを押すと該当Taskだけに絞り込めるようにする。

# 遅延判定

判定日はローカルPCの当日とし、日付だけで比較する。

| 判定 | 条件 |
|---|---|
| 完了 | `status: done` |
| 期限超過 | 未完了かつ `due < 今日` |
| 着手遅れ | `backlog` または `ready` で、`start < 今日` |
| 依存待ち | 未完了の先行Taskがある |
| 要注意 | 期限まで2日以内、または計画期間の経過率が進捗率を25ポイント以上上回る |
| 予定どおり | 上記に該当せず、開始日と期限が有効 |
| 日程未設定 | `start` または `due` がない |
| 日程矛盾 | `start > due` |

- 重大度は「日程矛盾 → 期限超過 → 着手遅れ → 依存待ち → 要注意 → 予定どおり → 完了」の順で扱う。ただし完了Taskは常に完了表示とする。
- 土日・祝日は初期実装では営業日換算せず暦日として扱う。
- `depends_on` の参照先が存在しない場合と自己参照は警告する。
- 循環依存はAPI側で検出して警告するが、自動修正しない。

# アクセス方法

- Kanbanヘッダーに `ガント` ボタンを追加する。
- ボタン位置は `WBSを生成` の右側とし、日程を見る操作と派生View生成を近くに置く。
- 押下すると同一タブで `/gantt.html` を開く。
- ガント画面のヘッダーに `Kanbanへ戻る`、`更新`、`今日` を配置する。
- 直接URL `http://localhost:<port>/gantt.html` でも開ける。
- READMEの操作説明に両方のアクセス方法を記載する。

# APIと構成

## API

`GET /api/gantt` を追加し、次を返す。

```json
{
  "generatedAt": "2026-09-19T00:00:00.000Z",
  "today": "2026-09-19",
  "range": { "start": "2026-09-01", "end": "2026-10-31" },
  "summary": {
    "total": 10,
    "doing": 2,
    "overdue": 1,
    "atRisk": 2,
    "unscheduled": 1
  },
  "tasks": [],
  "warnings": []
}
```

- APIはTask読み込み、進捗計算、日程判定、依存関係検証、表示範囲計算を担当する。
- ブラウザ側は表示と絞り込みだけを担当し、判定ロジックを重複させない。
- 現在日付を注入できる純粋関数として実装し、日付境界をテスト可能にする。

## UI

- Vanilla JS / CSSを継続し、新しいSPAフレームワークは導入しない。
- ガント描画はCSS Gridを基本とし、日付座標の計算だけJavaScriptで行う。
- Task数が数十件程度のPoCを対象とする。
- 一覧列を左に固定し、日付部分だけ横スクロールできる構成を優先する。
- 色だけに依存せず、ラベルとアイコンでも判定を示す。

# 実装ステップ

1. Task日程項目と遅延判定ルールを確定し、テンプレートとMarkdown検証を拡張する。
2. 既存サンプルTaskへ `start` と必要最小限の `depends_on` を追加する。
3. 完了条件のチェック状態から進捗率を算出する純粋関数を実装する。
4. 日程判定、依存関係検証、循環依存検出、表示範囲計算を実装する。
5. `GET /api/gantt` を追加する。
6. ガント画面の一覧、時間軸、横棒、今日線、凡例を実装する。
7. 日・週表示、今日へ移動、担当者・状態・Requirement・遅延判定の絞り込みを実装する。
8. Kanbanヘッダーとガント画面に相互導線を追加する。
9. 日程項目を既存Task詳細で確認・編集できるようにする。
10. WBS生成へ開始日、進捗率、依存Task、日程判定を追加する。
11. READMEとAGENTS.mdへ正本、派生View、アクセス方法、更新手順を追記する。
12. 単体テスト、APIテスト、主要画面の手動確認を行う。

# 検証

## 自動テスト

- `start` と `depends_on` の読み書きが既存Taskを壊さない。
- 完了条件0件、一部完了、全完了で進捗率が正しい。
- 期限当日、期限翌日、開始日前後の判定が正しい。
- `done` は期限を過ぎても期限超過にならない。
- 日程未設定、開始日が期限より後、存在しない依存先、自己参照、循環依存を検出できる。
- ガント表示範囲がTaskの日程から正しく求められる。
- APIレスポンスにTask、集計、警告が含まれる。

## 手動確認

- Kanbanの `ガント` から画面を開き、Kanbanへ戻れる。
- 直接URLから開ける。
- 今日線、横棒、進捗、判定色、凡例が一致する。
- 日・週切替と横スクロールが動作する。
- 絞り込みと集計件数が一致する。
- Task MarkdownまたはTask詳細で日程を変更し、更新後に反映される。
- PC幅と狭い画面幅の両方でTask名と日程を確認できる。

# 受入条件

- `npm start` 後、追加設定なしでガントチャートを表示できる。
- ヘッダーの `ガント` ボタンと直接URLの両方からアクセスできる。
- 期限超過、着手遅れ、依存待ち、要注意、予定どおり、完了、日程未設定を区別できる。
- Taskの開始日、期限、進捗率、担当者、状態、依存関係を確認できる。
- 遅延Taskだけに絞り込める。
- Task Markdownの変更が更新操作で反映される。
- ガント表示のためのDBや手編集用データファイルを追加していない。
- 既存テストと追加テストが成功する。

# リスクと軽減策

| リスク | 軽減策 |
|---|---|
| 開始日が未入力で表示できない | 日程未設定として一覧へ残し、入力が必要だと示す |
| 進捗率が実態とずれる | 完了条件から算出し、チェック項目がない場合だけ推定表示にする |
| Task数や期間が増えて見づらくなる | 週表示を初期値にし、絞り込みと横スクロールを用意する |
| 依存線が交差して読めない | PoCでは矢印線を描かず、先行Task IDと警告で示す |
| 休日を考慮しないため厳密な工程表にならない | 暦日計算であることを画面とREADMEに明記する |
| 色だけでは遅延種別が分からない | 色に加えて文字ラベルと凡例を表示する |
| WBSとガントで計算結果がずれる | 共通の整形・判定関数を利用し、両方をTask正本から生成する |

# レビューで確認する事項

本Planでは次を初期方針として採用する。変更希望がなければ、承認後はこの内容で実装する。

1. ガント画面は参照専用とし、日程編集はTask詳細から行う。
2. 進捗率は完了条件から算出し、手入力項目を増やさない。
3. 日程は暦日計算とし、休日カレンダーは導入しない。
4. 依存関係はID表示と警告までとし、矢印線は描画しない。
5. ガント画面は `/gantt.html` とし、Kanbanヘッダーから同一タブで開く。
6. 重いチャートライブラリやSPAフレームワークを追加しない。
