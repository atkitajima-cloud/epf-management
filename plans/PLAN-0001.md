# 目的

Markdown / GitをSingle Source of Truthとし、Planner風KanbanとローカルCodex CLI連携を備えた、日常利用可能な最小PoCを構築する。

# 調査結果

- リポジトリは初回空コミットのみで、既存実装はない。
- Node.js v24.15.0 / npm 11.12.1を利用可能。
- Codex CLI 0.153.0を利用可能。
- 非対話実行は `codex exec` で行える。
- `--ephemeral`、`--sandbox read-only`、`--output-schema`、`--output-last-message`、`--cd` を利用できる。

# アーキテクチャ

- Backend: Node.js標準モジュールのみ。HTTP API、静的配信、Markdown I/O、Git状態取得を担当する。
- Frontend: Vanilla HTML/CSS/JavaScript。Kanban、Drag & Drop、詳細編集、AI Chat、Git状態を提供する。
- Storage: `tasks/*.md` 等のMarkdownのみ。DBおよびUI固有の永続ストアは持たない。
- AI Adapter: 共通interfaceの `CodexAdapter` と `MockCodexAdapter` を用意する。
- Codex実行: リポジトリをread-onlyで参照させ、構造化JSONだけを返させる。Markdownへの変更はBackendが検証して行う。
- WBS: `tasks/*.md` から決定的に再生成する派生Viewとする。

# 実装ステップ

1. Markdownスキーマ、テンプレート、サンプルデータを作成する。
2. 安全なパス検証を含むMarkdown Reader / Writerを実装する。
3. Kanban APIとPlanner風UIを実装する。
4. Drag & Dropによるstatus更新を実装する。
5. Task詳細表示・編集を実装する。
6. Codex / Mock AdapterとAI Chatを実装する。
7. ChatからのTask作成と即時Kanban反映を実装する。
8. WBS生成とGit status表示を実装する。
9. README、AGENTS.mdを整備する。
10. API/UI/Markdown更新の動作確認と最終レビューを行う。

# PoC上の判断

- React等は導入しない。画面規模に対してビルド工程と依存が不要なため。
- YAMLライブラリは導入せず、Front MatterはPoCで必要な単純なscalar値に限定する。
- AI提案はJSONの操作候補として受け取り、既存要求の自動変更は許可しない。
- 明示的なタスク作成依頼のみ即時反映し、優先度変更や分割は提案表示に留める。
- Codexが未導入、未認証、失敗、タイムアウトの場合もMockで主要フローを継続する。

# 検証項目

- 起動と静的画面配信
- 6〜10件のTask読込と5列Kanban表示
- status変更時のFront Matter更新
- 詳細編集時のMarkdown更新
- MockおよびCodex Adapterの構造
- ChatによるTask作成と再読込
- WBS再生成
- Git status / 変更ファイル一覧
- DBファイルや外部SaaS依存がないこと
