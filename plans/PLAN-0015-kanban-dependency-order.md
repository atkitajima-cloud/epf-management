# Kanbanをガントと同じ依存順に並べる

## 目的

Kanbanの未完了カードを、ガントと同じ依存関係の順序で上から表示する。先行Taskを後続Taskより上に置き、Kanbanを見ても次に着手すべきTaskを判断しやすくする。

## 対象範囲

- 既存の`orderTasksByDependency`をKanbanの未完了カードにも共用する。
- Kanbanの各未完了列では、依存順の相対順序でカードを表示する。
- Done列は既存要件である完了日降順、同日ならTask ID降順を維持する。
- 共用する並び替え関数の単体テストを追加する。

## 対象外

- `depends_on`、Task状態、Kanban列構成、ドラッグ＆ドロップの変更
- 循環依存の自動修正、クリティカルパス計算
- Done列を依存順へ変更すること

## 設計判断

Kanbanは状態ごとに列が分かれるため、カード全体を一列に並べることはしない。表示対象全体でガントと同じ安定トポロジカルソートを一度行い、その結果を各未完了列へ分配する。これにより、同じ列の先行Taskと後続Taskはガントと同じ上下関係になる。

完了済みTaskは作業の着手順よりも直近の完了履歴を確認する用途が強いため、既存の完了日降順を維持する。未完了の着手順と、完了履歴の閲覧性を両立する。

## 実装手順

1. Kanban用の小さな並び替え関数を追加し、ガントの`orderTasksByDependency`を再利用する。
2. `app.js`のカード描画で、未完了列へ依存順、Done列へ完了日順を適用する。
3. 依存関係を持つ未完了Taskと完了Taskが混在するケースを単体テストする。
4. `npm test`を実行し、Kanban画面で未完了カードの順序とDone列の順序を確認する。

## リスクと復旧

| リスク | 軽減策 |
| --- | --- |
| 状態列が分かれるため、異なる列のカードは縦に比較できない | 各列内の相対順をガントと共通化し、状態列の役割は維持する。 |
| Done列の既存ソートが変わる | Done列は依存順にせず、既存の完了日順をテストで固定する。 |
| 循環依存がある | ガントと同じく解決できないTaskを末尾へ置き、Task正本を自動修正しない。 |

## 実施結果

- `orderTasksByDependency`をKanban用の並び替え関数から再利用した。
- 未完了列はガントと同じ依存順、Done列は既存の完了日降順で表示するようにした。
- 依存順とDone列の順序を単体テストし、`npm test`で回帰確認した。
