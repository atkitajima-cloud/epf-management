# 背景

EPF PoCは成功条件を達成し、Task起点のbranch、Pull Request、CI/CD、CDK deployまでを一周した。一方、PoC総括の横断評価で、管理方式の重要な部分が人間とAIが文章のルールを守ることに依存していると確認された。

本番EPFは2027年6月リリースを目標とし、2026年10月末から設計・実装フェーズへ入る。開発メンバーは最大5人で、全員がAI駆動開発の初心者である。AIの産出速度に対して人間のレビュー能力は人数に比例しないため、成果物の検証を人の注意力だけに頼る運用は成立しない。

# 要求

設計・実装フェーズの開始までに、5人が安全に並行作業できる開発基盤を整備すること。改善対象と根拠は[PoC総括とチーム開発レディネス評価](../../epf-project/docs/references/poc-retrospective-and-team-readiness.md)のIMP-01からIMP-08を正本とする。

本番EPFのTask管理基盤にはepf-managementを継続採用する。Markdown / Gitを正本とすることでAIが追加の接続なしにTaskを読めること、GitLab未経験者が多いこと、正本がMarkdownであるため将来の移行コストが低いことを理由とする。

# 受入条件

- 規約違反、リンク切れ、Front Matterの不正値、完了条件の未達を機械が検出し、人の目視に依存しない。
- 4repoの共有・復元経路が確立し、別端末から同じ基準版を取得して作業を再開できる。
- 複数人が同時にTaskを作成・更新しても、ID衝突と更新消失が起きない。
- Pull Requestの検証・承認・権限分離が強制され、未検証の変更が環境へ到達しない。
- API契約と実装の適合、および検証済み成果物と配布物の同一性を機械で確認できる。
- 新規メンバーが、正本・作業規則・最初の作業を案内から辿れる。
