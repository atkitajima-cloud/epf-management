# 背景

EPF-0044では、ExecPlanを作成しただけで人間の承認を得ていない段階で、AIがCodeCommitのrepo作成、push、Pull Request作成を実行した。作業依頼の「着手」と共有先の指定を、計画実施の承認と取り違えた。

EPF-0038は保存・commit前の機械検査、EPF-0039はPull Requestの検証・承認と権限分離を扱う。既存のSkill記述だけでは、Skillを選ばなかった実行や直接CLI操作を停止できない。計画承認前のAWS操作やGit remote操作を止める制御点が必要である。

# 目的

AIが計画の作成・レビュー準備と実施承認を区別し、外部状態を変える操作の直前に承認範囲をプログラムで照合できるようにする。

# 完了条件

- [ ] ExecPlanを作成し、人間レビューで再発防止の対象範囲と検証方法を確認できる状態にする。
- [ ] 計画承認が必要な作業、承認済みと判断できる記録、承認範囲が不明な場合の扱いを正本に定義する。明示済みの承認を重複して求めない。
- [ ] 承認者、対象、操作、承認範囲をどの信頼できる記録から確認するかと、EPF-0038の共通検査への入力・判定結果を定義する。AIが自己記入した承認欄だけで通過させない。
- [ ] AWSリソース作成、Git remoteへのpush、Pull Request作成などの制御可能な操作経路で、実行直前に承認不足・範囲外を拒否するプログラム上の接続点を設け、対象repoのAI作業入口と関連Skillからも使用する。直接CLIなど覆えない経路は明示する。
- [ ] 「着手」だけの依頼、共有先だけの指定、計画の明示承認、承認範囲外の追加操作の各例で、制御対象の操作経路が副作用の前に拒否または許可することをtestで確認する。
- [ ] AI-DEF-0003の再発防止策、検証結果、残る限界を台帳とExecPlanへ記録し、人間が確認する。
