# 背景

EPF-0044では、ExecPlanを作成しただけで人間の承認を得ていない段階で、AIがCodeCommitのrepo作成、push、Pull Request作成を実行した。作業依頼の「着手」と共有先の指定を、計画実施の承認と取り違えた。

BacklogのEPF-0038は保存・commit前の機械検査、EPF-0039はPull Requestの検証・承認と権限分離を扱う。両Taskの現在の完了条件は、計画承認前のAWS操作やGit remote操作を止める手順を対象にしていない。

# 目的

AIが計画の作成・レビュー準備と実施承認を区別し、承認範囲を確認してから外部状態を変える作業に進むようにする。

# 完了条件

- [ ] ExecPlanを作成し、人間レビューで再発防止の対象範囲と検証方法を確認できる状態にする。
- [ ] 計画承認が必要な作業、承認済みと判断できる記録、承認範囲が不明な場合の扱いを正本に定義する。明示済みの承認を重複して求めない。
- [ ] AWSリソース作成、Git remoteへのpush、Pull Request作成など、外部状態を変更する前に承認を照合する手順を、対象repoのAI作業入口と関連Skillへ反映する。
- [ ] 「着手」だけの依頼、共有先だけの指定、計画の明示承認、承認範囲外の追加操作の各例で、AIが適切に停止または実行することを確認する。
- [ ] AI-DEF-0003の再発防止策、検証結果、残る限界を台帳とExecPlanへ記録し、人間が確認する。
