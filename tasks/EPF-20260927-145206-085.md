# 背景

Task・ExecPlan同期Skillは状態遷移ゲートとして広い責務を持つ一方、複数の正本文書を常時参照し、同じ判断と検査を繰り返している。改善提案とClaude Code Opusの独立レビューにより、Skill実行漏れだけでなく、`done`の直前状態をhookが検査しないこと、人間確認overrideが遷移先に束縛されないこと、hook全体の回帰テストがないことも判明した。安全上の穴を先に塞ぎ、運用を増やさずに正本とSkillを軽量化する必要がある。

# 目的

Task状態遷移の安全性を維持・強化しながら、正本の重複とSkillの無条件な参照・重複確認を減らし、Skillを`epf-task-transition-gate`として再編する。
