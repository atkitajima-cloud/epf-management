# 背景

Task・ExecPlan同期Skillは状態遷移ゲートとして広い責務を持つ一方、複数の正本文書を常時参照し、同じ判断と検査を繰り返している。改善提案とClaude Code Opusの独立レビューにより、Skill実行漏れだけでなく、`done`の直前状態をhookが検査しないこと、人間確認overrideが遷移先に束縛されないこと、hook全体の回帰テストがないことも判明した。安全上の穴を先に塞ぎ、運用を増やさずに正本とSkillを軽量化する必要がある。

# 目的

Task状態遷移の安全性を維持・強化しながら、正本の重複とSkillの無条件な参照・重複確認を減らし、Skillを`epf-task-transition-gate`として再編する。

# 完了条件

- [x] ExecPlanを作成し、人間レビューで実装範囲と検証方法を確認できる状態にする。
- [ ] commit前hookが、削除を除く`done`遷移について直前状態が`review`であることを検査し、正常系・拒否系の回帰テストがある。
- [ ] 人間確認overrideが遷移先に束縛され、UIは保存ごとに明示された確認だけを記録し、既存の確認を自動で再利用しない。
- [ ] `doing`・`review`・`done`の証跡保存前にTask内容を最終化する操作順と、Task・ExecPlanの安全なクローズ順序が正本に定義される。
- [ ] DD-01-01〜06と4repoの`AGENTS.md`について、状態遷移、品質ゲート、日時、repo別完了条件の正本分担と起動条件が一致する。
- [ ] DD-01-06から、各ゲートの検査対象、対象範囲、検査条件、検査項目、検査しないもの、正本コードを判断できる。
- [ ] Skillを`epf-task-transition-gate`へ改名し、正本、Claude Code wrapper、現行ルール、動作するリンクを同一変更で切り替える。
- [ ] Skillの常時参照を状態遷移に必要な最小範囲へ減らし、repo別手順、AI不備台帳、設計Task引き渡しは該当時だけ参照する。
- [ ] 既存のTask保存API、Front Matter検証、`doing`・`review`・`done`証跡、完了条件検査に回帰がなく、4repoの文書検査が成功する。
- [ ] Claudeレビューの採用・対象外・将来検討をExecPlanへ記録し、対象外項目を暗黙に運用へ追加しない。
