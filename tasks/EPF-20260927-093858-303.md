# 背景

AIがTaskを`doing`へ遷移させた際、同期Skillを実行していなくても既存のcommit前hookでは検出されない。AI-DEF-0010で指摘された初回の漏れを、既存の`review`／`done`と同じ証跡ゲートで防ぐ必要がある。

# 目的

AIによる`doing`遷移には同期証跡を必須にし、人間が明示的に確認した遷移は既存の人間確認overrideで許可する。

# 完了条件

- [ ] `doing`への状態遷移を既存のcommit前証跡検査の対象に追加する。
- [ ] `sync_target: doing`をTask保存APIとFront Matter検証で扱えるようにする。
- [ ] `human_checked`とフィンガープリントが有効な場合、既存の`review`／`done`と同様に`doing`遷移の検査を通過できる。
- [ ] `review`／`done`の未チェック完了条件・状態遷移制約・既存証跡検査を変更しない。
- [ ] `doing`の証跡あり・証跡なし・人間確認overrideの回帰テストと記録検査を成功させる。
- [ ] 品質ゲート設計書、同期Skill、AI-DEF-0010の対応状況を実装結果に整合させる。

# メモ

ExecPlanの人間承認後に実装する。Task作成時点では`doing`同期証跡をまだ保存できないため、既存ルールに従いExecPlan作成と同じ作業ターンで着手記録を作る。
