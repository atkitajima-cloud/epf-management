# 背景

Pull Requestごとの自動CI、必須check、branch保護、承認強制はPoCの対象外としていた。AI principalには`AdministratorAccess`を付与しており、責務分離は運用ルールにとどまる。レビュー担当も1人に集中している。

# 目的

未検証・未承認の変更が環境へ到達しない状態にし、AIの産出速度に耐えるレビュー体制を設計する。

## EPF-0038からの引き渡し

- 4repoのcommit前hookは`--no-verify`、hook設定変更、直接のGit操作で迂回できる。共有先では必須checkとbranch保護を適用し、検査失敗の差分が`main`へ到達しないことを確認する。
- ExecPlanの`計画承認状態: approved`とTaskの`accepted_by`は、同一PC・同一Git identity・同一AWS権限を使うAI自身も編集できる。CodeCommitのapproval ruleとAI／人間のIAM principal分離により、AIの自己承認と承認後の差分追加を拒否する。（2026-09-26: 利用者判断によりIAM principal分離はEPF-0039の対象外とした。承認1件必須とPR作成者本人の承認禁止というCodeCommitの既定動作、および運用上AIが承認・merge操作を行わない手順で、当面の自己承認リスクに対応する。）
- EPF Managementには利用者認証がなく、受入APIの呼出者は証明されない。人間受入の証跡を権限で保証する範囲と確認方法を設計する。
