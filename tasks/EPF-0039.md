# 背景

Pull Requestごとの自動CI、必須check、branch保護、承認強制はPoCの対象外としていた。AI principalには`AdministratorAccess`を付与しており、責務分離は運用ルールにとどまる。レビュー担当も1人に集中している。

# 目的

未検証・未承認の変更が環境へ到達しない状態にし、AIの産出速度に耐えるレビュー体制を設計する。

# 完了条件

- [ ] ExecPlanを作成し、人間レビューで実装範囲と検証方法を確認できる状態にする。
- [ ] IMP-02の完了条件のうち、採用した範囲を満たす。
- [ ] 検証失敗、未承認、承認後の追加変更が、いずれも許可されないことを実際に試して確認する。
- [ ] 機械・AIレビュー・メンバー相互レビュー・責任者レビューの分担を定義する。
