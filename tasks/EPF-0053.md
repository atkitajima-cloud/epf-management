# 背景

EPF-0038で、Review中のTaskへ受入記録を別操作で保存するAPI、`accepted_by`と`actual_completed_at`、および「人間受入を記録」ボタンを追加した。利用者はこのボタンを運用で使用しておらず、認証のないアプリでは操作主体の証明にもならない。ReviewからDoneへ進めるために二段階の操作を要求する現在の設計は、実運用に合っていない。

# 目的

独立した受入記録操作を廃止し、ReviewからDoneへの状態変更を一操作で完了できるようにする。完了日時と既存Taskの扱いは、記録の整合を保つ方式を人間承認済みExecPlanで決定する。

# 完了条件

- [ ] ExecPlanを作成し、削除範囲、完了日時の記録方法、既存の受入記録の扱い、検証方法について人間承認を得る。
- [ ] 承認済みの範囲で、受入記録API、画面の「人間受入を記録」ボタン、`done`前の受入証跡必須チェックを削除または置換する。
- [ ] ReviewからDoneへの状態変更を一操作で行え、承認済み設計どおりに完了日時を記録できる。
- [ ] 既存TaskとTask／ExecPlan同期Skill、品質ゲート設計書、関連Planを整合させる。
- [ ] 正常・異常・既存Taskのケースを自動testし、主要UI操作を確認する。
