# 背景

AIが`review`／`done`へTaskを進める際に`epf-task-execplan-sync`を実行せず、または実装・test・自己レビュー・commitを完了する前に状態変更する不備がAI-DEF-0010で検出された。現行のTask保存APIとcommit前hookは、同期Skillの証跡を検査しない。

一方で、認証のないEPF Managementでは人間のUI操作とAIの操作を技術的に識別できない。人間がUIから状態変更したTaskをCommit & Pushする経路は、明示的な人間確認を記録すれば同期Skill証跡なしで通せる必要がある。

# 目的

既存のTask保存API、Front Matter検証、commit前hookを拡張し、AIがGit経由で`review`／`done`へ変更したTaskを共有する際は同期Skillの正常実行証跡を必須にする。人間確認欄があるTaskは手動overrideとして証跡なしで共有できるようにする。

# 完了条件

- [x] ExecPlanを作成し、証跡のFront Matter形式、無効化条件、人間確認override、既存Taskの扱い、検証方法について人間承認を得る。
- [x] 同期Skillが正常終了時に、対象Task・遷移先・対象内容へ紐付く機械可読な`passed`証跡をTaskへ保存できる。
- [x] Task保存APIとcommit前hookが、`review`／`done`への変更で有効な同期証跡または人間確認overrideを要求し、欠落・不正・期限切れの証跡を拒否する。
- [x] Task本文、完了条件、ExecPlan参照など証跡の対象内容を変更した場合、同期証跡と人間確認overrideを無効化する。
- [ ] UIで人間確認overrideを記録でき、人間のCommit & Pushは有効なoverrideがあれば同期証跡なしで通る。
- [x] 既存のFront Matter検証、未チェック完了条件の拒否、Review→Done制約を維持し、正常・異常・直接編集・既存Taskのケースを自動testする。
- [x] 設計書、同期Skill、AI-DEF-0010を更新し、`npm test`と記録検査が成功する。
