# 背景

AIがGit経由で`review`／`done`へ状態遷移する際に、`epf-task-execplan-sync`の実行漏れを防ぐ。人間がUIで状態を変更したTaskのCommit & Pushは、人間確認を明示すれば同期Skill証跡なしでも通せるようにする。

# 目的

既存のTask保存API、Front Matter、commit前hookを用いて、AIのGit経由の`review`／`done`遷移には同期Skillの有効な証跡を要求する。新たな品質ゲート基盤は作らない。

# 完了条件

- [x] ExecPlanを作成し、同期証跡と人間確認overrideの形式・無効化条件を記録した。
- [x] 同期Skillが正常終了時に`passed`証跡をTaskへ記録する。
- [x] 保存APIとcommit前hookが、AIの`review`／`done`遷移で有効な同期証跡または人間確認overrideを検査する。
- [x] Task本文・完了条件・ExecPlanリンクなどの意味のある変更で証跡とoverrideを無効化する。
- [x] 人間がUIでTaskを`done`まで遷移でき、後続のCommit & Pushは同期Skill証跡なしでも通る。
- [x] Front Matter検証、未チェック完了条件、Review→Done制約、既存Taskの回帰テストを維持する。
- [x] 設計書、同期Skill、AI-DEF-0010を更新し、`npm test`と記録検査を成功させた。
