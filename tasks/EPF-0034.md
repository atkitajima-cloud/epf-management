# 背景

EPF ManagementのTaskを起点に、frontendとbackendを含む複数のfeature branch、Pull Request、merge commit、Pipeline結果を追跡する運用が未定義である。EPF-0033を最初の実例として、branch名へTask IDを含める方針を検討した。

# 目的

Taskとbranch・Pull Requestを対応付ける開発フローを設計し、既存のTask同期SkillとAIコードレビューSkillへ必要な最小更新を行う。

# 完了条件

- [x] ExecPlanを作成し、人間レビューで承認する。
- [x] Task:branchを1:Nとする命名規則、repo横断時の扱い、commit・Pull Requestの記載規則を設計書に記録する。
- [x] Task着手からmain merge、Pipeline確認、Task完了までの標準フローを記録する。
- [x] Taskの実装記録にbranch、Pull Request、merge commit、Pipeline結果を残す同期ルールを定義する。
- [x] `epf-task-execplan-sync`と`epf-code-review`の入力・完了確認を設計と整合させる。
- [x] EPF-0033が新しい運用に従って着手できる状態にする。
