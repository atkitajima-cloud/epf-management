# 背景

本番EPFの要求仕様はExcelで作成され、要求Noで識別される。これをMarkdownへ落として`epf-project`へ置く方針だが、EPF ManagementのTaskは`requirement`をREQ-0000形式に限定して検証しており、画面のRequirement選択肢は`epf-management/requirements/`だけを読む。

正本と参照方式を決めないまま運用を始めると、同じ要求が二箇所に書かれるか、Taskから要求を辿れなくなる。要求仕様を作成している現在が、最も安く決められる時期である。

# 目的

要求の正本、Markdownの位置づけ、TaskからRequirementへの参照方式を確定し、アプリ改修の要否を判定する。

# 完了条件

- [ ] ExecPlanを作成し、人間レビューで判断範囲と影響を確認できる状態にする。
- [ ] Excelと落とし込んだMarkdownのどちらが正本かを決め、派生Viewとする場合は再生成手順と直接編集禁止を明示する。
- [ ] `epf-project`側の置き場とディレクトリ名を決める。`epf-management/requirements/`と同名で意味が異なる状態にしない。
- [ ] TaskからRequirementを辿る方式を決める。REQ-0000形式を索引として維持するか、形式検証と選択肢の取得元を変更するかを判定する。
- [ ] 要求No、索引、Taskの三者を相互に辿れることを実例で確認する。
- [ ] 実装が必要な決定について後続Taskと依存関係を記録する、または実装不要理由を記録する。
