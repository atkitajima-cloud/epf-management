# 背景

本番EPFの要求仕様はExcelで作成され、要求Noで識別される。会社の承認プロセスがExcelで回るため、Excelを要求の正本とする。

一方、AIとGitが扱えるのはテキストである。要求をMarkdownへ手作業で写すと、更新のたびに変換コストが発生し、Excelとの乖離も避けられない。`views/wbs.md`と同じく、**Markdownを再生成可能な派生View**として扱う方針とする。

あわせて、EPF ManagementのTaskは`requirement`をREQ-0000形式に限定して検証しており、画面のRequirement選択肢は`epf-management/requirements/`だけを読む。要求仕様を`epf-project/docs/requirements/`へ移管するため、取得元と参照を更新する必要がある。

# 目的

Excelを正本としたまま、既存の要求仕様を共通ドキュメントとして参照・追跡できる状態にする。Excelからの変換自動化は後続作業で扱う。

# 完了条件

- [x] `epf-management/requirements/`の既存Requirementを`epf-project/docs/requirements/`へ移管し、移管元を残さない。
- [x] EPF ManagementのRequirement一覧とTask作成時の存在確認が、移管先を参照する。
- [x] README、用語集、Task、Requirement本文のパス参照を移管先に整合させ、リンク切れがないことを確認する。
- [x] `REQ-0000`形式をTaskとRequirementを結ぶ索引として維持し、既存Taskが参照できることを確認する。
