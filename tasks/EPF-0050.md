# 背景

本番EPFの要求仕様はExcelで作成され、要求Noで識別される。会社の承認プロセスがExcelで回るため、Excelを要求の正本とする。

一方、AIとGitが扱えるのはテキストである。要求をMarkdownへ手作業で写すと、更新のたびに変換コストが発生し、Excelとの乖離も避けられない。`views/wbs.md`と同じく、**Markdownを再生成可能な派生View**として扱う方針とする。

あわせて、EPF ManagementのTaskは`requirement`をREQ-0000形式に限定して検証しており、画面のRequirement選択肢は`epf-management/requirements/`だけを読む。要求NoとTaskをどう結ぶかを決める必要がある。

# 目的

Excelを正本としたまま、要求仕様をテキストとして参照・検査・追跡できる状態にする。変換は自動化し、運用時の手作業をゼロにする。

# 完了条件

- [ ] ExecPlanを作成し、人間レビューで実装範囲と検証方法を確認できる状態にする。
- [ ] Excelから要求No単位のMarkdownを生成するスクリプトを用意し、再実行しても同じ結果になることを確認する。
- [ ] 生成物の冒頭に、元ファイル名、更新日、内容のハッシュ、および直接編集しない旨を出力する。
- [ ] 生成スクリプトと生成物の置き場とディレクトリ名を決める。`epf-management/requirements/`と同名で意味が異なる状態にしない。`epf-project`へ置く場合は、実装コードを置かない原則との整理を記録する。
- [ ] TaskからRequirementを辿る方式を決める。REQ-0000形式を索引として維持するか、形式検証と選択肢の取得元を変更するかを判定する。
- [ ] 要求Noが振り直されない運用であることを確認し、崩れる場合の対処を記録する。
- [ ] 要求No、索引、Taskの三者を相互に辿れることを実例で確認する。
- [ ] 実装が必要な決定について後続Taskと依存関係を記録する、または実装不要理由を記録する。
