# 背景

EPF-0043では、AIが計画承認と判断事項への回答を成果物の最終受入と取り違え、Taskを`done`、ExecPlanを`completed`へ進めた。完了時に状態変更で必須の`epf-task-execplan-sync`を使用せず、Skill名と対象Taskの開始時通知もなかった。人間の指摘により`review`と`active`へ戻した。

# 目的

AIが作業の完了報告を人間の受入と混同せず、Taskを`done`へ保存する前にownerの受入記録をプログラムで確認できるようにする。

# 完了条件

- [ ] ExecPlanを作成し、人間レビューで再発防止の範囲と検証方法を確認できる状態にする。
- [ ] 計画承認、実施中の判断、成果物の最終受入を区別し、Taskを`review`から`done`へ進める際に必要な人間の意思表示と記録方法を定義する。
- [ ] 受入者本人の記録元とEPF-0038の共通検査への入力・判定結果を定義する。AIが自己記入したFront Matterだけを人間受入とみなさない。
- [ ] EPF ManagementのTask保存経路で、受入未了の`done`を拒否し`review`と空の`completed_at`を維持する。直接Markdown編集の検出はEPF-0038のstaged検査へ接続し、Task／ExecPlan同期のSkillにも同じ確認を反映する。
- [ ] 新規セッションでTaskの状態変更を扱う例でも、同期Skillの選択、開始時通知、受入記録の照合を省略せずに実行できることを確認する。
- [ ] 計画だけの承認、作業方針への回答、成果物の受入、明示された完了指示の例で、Task保存時とstaged検査時の許可・拒否をtestし、拒否時にTaskとExecPlanの状態が進まないことを確認する。
- [ ] AI-DEF-0004の対応結果と検証証跡を台帳へ記録し、人間が確認する。
