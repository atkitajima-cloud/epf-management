# Task削除を論理削除へ変更し削除済み表示を追加する

## 目的

Taskの物理削除を論理削除へ変更する。削除済みTaskはMarkdownと関連リンクを保持し、Kanbanのdone列で通常の完了Taskと区別して表示する。

## 対象範囲

- `app/lib/markdown.js` と `scripts/check-records.mjs` のTask検証、論理削除、更新禁止
- `app/public/app.js` と `app/public/index.html` の削除済み表示・操作禁止
- `app/test/markdown.test.js` と `app/test/git.test.js` の回帰テスト
- 未コミットのEPF-0046物理削除を復元し、論理削除として記録する

## 対象外

- 削除済みTaskを元に戻す復元操作
- 過去の完了TaskやExecPlan本文の書き換え

## 受け入れる設計判断

- Task Markdownは削除しない。`status: done` と `deleted_at`（ISO 8601）を記録する。
- `deleted_at` を持つTaskは、通常の完了に必要な受入記録・未チェック完了条件の検証対象外とする。これは完了を偽装しないための明示的な削除済み例外である。
- 削除済みTaskはdone列に残し、「削除済み」と削除日時を表示する。編集、状態変更、再削除は受け付けない。

## 実装手順

1. EPF-0046をGitの直前版から復元し、記録・リンクを保全する。
2. `deleted_at` のFront Matter保存・検証を追加し、`deleteTask` を物理削除から論理削除へ置換する。
3. 削除済みTaskの更新・状態変更を拒否する。
4. Kanbanカードと詳細画面に削除済み状態を表示し、操作を無効化する。
5. 論理削除、通常完了、削除済み操作拒否、物理削除パスのGit stagingをテストする。
6. `npm test`、`node scripts/check-records.mjs`、差分検査を実行する。

## 検証方法

- 未完了Taskを削除すると、同じMarkdownファイルが残り、`status: done` と `deleted_at` が保存される。
- 削除済みTaskは一覧とdone列に表示され、通常の完了と区別できる。
- 削除済みTaskの編集・再削除・状態変更はAPIで拒否される。
- `npm test` と記録検査が成功する。

## リスクと未確定事項

- `done` はKanban配置用の既存値であり、削除済みかどうかは必ず`deleted_at`で判別する。
- 復元操作は今回実装しないため、削除前の確認ダイアログを維持する。
