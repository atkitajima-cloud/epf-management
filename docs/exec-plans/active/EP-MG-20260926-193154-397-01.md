## 目的

Requirement → Task → ExecPlan → push済み実装commit の追跡経路を作る。commitリンクはリモートGitサービスのcommit履歴画面へ向け、そこから差分・変更ファイル・履歴を辿れるようにする。

## 対象範囲

- `.agents/skills/epf-task-execplan-sync/SKILL.md` の`review`手順と`done`手順
- `docs/exec-plans/TEMPLATE.md` の実装記録書式
- `epf-project`のAI Skill運用設計書

## 対象外

- Task保存API、Front Matter、pre-commit hook、`check-records.mjs`の品質ゲート変更
- commit URLの疎通検査や、リンク未記録を機械的に拒否する検査
- 過去のExecPlanへの一括追記

## 決定事項

- 実装を伴うTaskは、対象repoごとにpush済みcommitのリモートURLをExecPlanの`実装記録`へ記載する。
- 表示はrepo名、短縮commit SHA、commit URLを用いる。複数commit・複数repoは行を追加する。
- 設計・調査など実装commitが存在しないTaskは、同じ欄へ実装不要の理由を記録する。
- 記録は実装commitのpush後、Taskを`review`へ進める前に行う。同期Skillの`review`手順で、実装Taskはpush済みcommitとExecPlanの記録を、実装不要Taskは理由の記録を確認する。`done`手順では同じ情報が最終状態として残っていることを再確認する。
- これは記録運用であり、新たな自動品質ゲートは導入しない。

## 実装手順

1. ExecPlanテンプレートに`実装記録`節を追加し、commitリンクと実装不要理由の書式を定義する。
2. 同期Skillの`review`手順へ、対象Taskが実装を伴うか判定し、push済みcommitの確認とExecPlanへのcommitリンク記録、または実装不要理由の記録を確認する手順を追加する。`done`手順には同じ記録が最終状態として残っていることの再確認を追加する。
3. AI Skill運用設計書へ、記録時点、URLの対象、複数repo／複数commit、例外の扱いを追記する。
4. 既存のhook・API・記録検査を変更していないことを差分で確認し、リンク検査を実行する。

## 検証方法

- テンプレートから、実装Task用のcommitリンクと実装不要Task用の理由の双方を記録できることを確認する。
- push済みcommit記録の確認を含めて同期Skillが正常終了し、その証跡をもって`review`へ進めることを確認する。
- 人間レビュー開始時点で、Requirement → Task → ExecPlan → push済み実装commitを辿れることを確認する。
- 同期Skillの`done`手順が、同じ記録の最終状態を再確認することを確認する。
- `node scripts/check-records.mjs` が成功することを確認する。
- API、hook、テスト実行の条件を追加していないことを差分確認する。

## 完了条件

- 実装TaskのExecPlanからpush済みcommit履歴へリンクで辿れる。
- 実装不要Taskにも理由が残り、空欄のままにならない。
- `epf-task-execplan-sync`の`review`手順が、記録確認後にだけ人間レビューへ進める。
- 人間レビュー開始時点で、ExecPlanからレビュー対象のpush済み実装commitを辿れる。
- `epf-task-execplan-sync`の`done`手順が、同じ記録の最終状態を再確認する。
- 新しい品質ゲートや機械的な拒否条件を増やしていない。

- push前のローカルcommitを記録すると他者が追跡できないため、記録対象はpush済みcommitに限る。
